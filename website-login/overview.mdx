Set up your Bot to access websites that require a login. BrowserAct supports three methods:

- **Account credentials:** Store login details in Account Credentials and authorize your Bot to use them.
- **Import cookies:** Reuse a website session you have already signed in to.
- **Manual login:** Sign in yourself in the Bot's browser.

This guide applies to your own Bots built with Agent or Workflow. You can combine methods, and your Bot reuses its setup across runs.

> For tasks that require login, we recommend **Standard Browser with a Static Proxy** to reuse your login session and keep a consistent IP address. [Learn how to purchase and use a Static Proxy](https://docs.browseract.com/browser-proxy/proxy/static-proxy-purchase-use?co-from=link-Docs#purchase-a-static-proxy).

## Choose the right login method

### Which method should I use?

| Your situation | Recommended method | How it helps |
| --- | --- | --- |
| The website uses authenticator-app two-factor authentication (2FA) | **Account credentials** | Add an Authenticator App Key so BrowserAct can generate supported time-based codes (TOTP). |
| The website has no 2FA | **Import cookies** or **Account credentials** | Reuse a signed-in session, or let the Bot sign in with saved credentials. |
| You do not want to store your password in BrowserAct | **Import cookies** | Sign in locally and import the session cookies. |
| The website frequently changes its login page | **Import cookies** | Reuse a signed-in session without relying on the login page's layout. |
| The website requires email or SMS verification | **Import cookies** or **Manual login** | Complete verification yourself, then import the session or save it in the Bot's browser. |
| You want to complete login or verification in the Bot's browser | **Manual login** | Open the browser, sign in, and save the session. |

**Standard Browser** supports all three methods and saves successful login updates for future runs. **Rotating Browser** supports authorized account credentials only and does not save its temporary session for future runs. Rotating Browser was previously named Private Browser.

![Rotating Browser supports Account credentials; Import cookies and Log in manually are unavailable](/images/website-login-rotating-browser-limits.png)

Credentials are the account details used to sign in. Login state is the browser session a website recognizes as signed in. Authorizing credentials or importing cookies does not guarantee that the website will accept the login.

### Open Login settings

**Agent Build:** Below the prompt input box, select `This website needs login` to use Standard Browser and open `Login settings`. Select the gear icon to reopen the panel. Leaving the checkbox unselected uses Rotating Browser.

![Select This website needs login below the Agent prompt to open Login settings](/images/website-login-agent-entry.png)

Credentials and cookies are optional before Build. BrowserAct first checks the existing session, then tries a matching authorized credential. If login still needs your help, Build requests manual assistance.

**Workflow Build:** Open the build canvas and select `Start`. Under `Default Browser`, turn on `This website needs login`. Use the gear icon to reopen `Login settings`.

![Open Login settings from Default Browser in the Workflow Start node](/images/website-login-workflow-entry.png)

The switch is on for Standard Browser and off for Rotating Browser. Turning it on saves Standard Browser. Turning it off requires confirmation to switch modes and clear Standard Browser history, cookies, and cache.

**Existing Bot:** Open the Bot's `Browser settings` tab and find `Website login`. After a Workflow Bot has been published, use this tab for login changes.

> **Login settings are locked while a task is running in the Bot's browser.** Wait for all tasks in that browser to finish before making changes.

![A running task blocks changes to the Bot's Login settings](/images/website-login-running-task-limit.png)

## Method 1: Use account credentials

Store account details in Account Credentials and authorize the Bots that need them. Account credentials work with both Standard Browser and Rotating Browser.

### Add an account credential

#### Option 1: From Build and Browser settings

1. Open your Bot and select the `Browser settings` tab.
2. Under `Website login`, select `Settings` on the `Account credentials` card.
3. In `Credential Authorization`, select `Add New Credential`.

Credentials saved through this entry are **automatically authorized for the current Bot**.

![Open Account credentials Settings from the Bot's Browser settings tab](/images/website-login-account-credentials-entry.png)

#### Option 2: From Account Credentials

1. Open `Account Credentials` from the sidebar.
2. Select `Add`.

![Select Add on the Account Credentials page to open the Add Credential form](/images/credential-center-add.png)

After saving, authorize a Bot using the steps in the next section.

#### Complete the credential form

Both entries use the same form:

1. Enter a name in `Credentials Name`, such as `Google Account`.
2. Under `Identifier(s)`, enter the field name in `Key` and your account details in `Value`. Match the website's login fields, such as email, username, or account ID.
3. Select `Add Another Identifier` if the website needs another account field.
4. Enter the `Password`.
5. For supported authenticator-app 2FA, add an `Authenticator App Key` using `Key` or `QR Code`.
6. Enter a `Usage Rule`, such as `Use for Google account sign-in`.
7. Select `Confirm`.

**Two-field login:** Add one identifier and a password. For example, Instagram accepts an email, username, or phone number as the identifier.

![Map an Instagram login to one Identifier and Password](/images/credential-two-login-fields.png)

**Three-field login:** Add both identifiers and a password. For example, AWS IAM uses Account ID, IAM username, and Password.

![Map an AWS IAM login to two Identifiers and Password](/images/credential-three-login-fields.png)

An Authenticator App Key generates supported time-based codes (TOTP). For email or SMS codes, complete verification yourself using [manual login](#method-3-log-in-manually), or import cookies from a session you have already verified.

### Authorize a Bot to use a credential

Use either entry below to authorize an existing credential. You only need to grant each Bot access once.

#### From the current Bot's Login settings

Choose which credentials **the current Bot** can use:

1. Open the Bot's `Browser settings` → `Website login`.
2. Select `Settings` on the `Account credentials` card.
3. In `Credential Authorization`, open `Not Authorized`.
4. Select the checkboxes next to the credentials you want this Bot to use.
5. Select `Authorization` at the bottom of the panel.

![Select credentials in Not Authorized, then select Authorization for the current Bot](/images/credential-authorize-current-bot.png)

The `Authorized` tab lists the credentials this Bot can use. You can also access credential authorization from Agent or Workflow `Login settings` during setup.

#### From Account Credentials

Choose which Bots can use **the selected credential**:

Open `Account Credentials` and select the credential's key icon in `Actions`.

![Select the credential's key icon to open Credential Authorize](/images/credential-workflow-authorization-entry.png)

1. In `Credential Authorize`, click the Bot selection box.
2. Open `Not Authorized` and select the checkboxes next to the Bots you want to authorize.
3. Select `Authorization` at the bottom of the panel.

![Select Bots in Not Authorized, then select Authorization](/images/credential-authorize-bots.png)

### Update and manage credentials

#### Edit a credential

In `Account Credentials`, select the credential's pencil icon in `Actions`. Update its details, using `Change Password` if needed, then select `Confirm`.

![Edit a credential and select Confirm](/images/edit-credential.png)

#### View usage records

Select the usage-record icon in `Actions` to view the credential's usage history.

![Open credential usage records from Actions](/images/credential-usage-records.png)

#### Revoke authorization

##### From the current Bot's Login settings

Remove **the current Bot's access to a credential**:

1. Open the Bot's `Browser settings` → `Website login`.
2. Select `Settings` on the `Account credentials` card.
3. In `Credential Authorization`, open `Authorized`.
4. Find the credential and select `Remove Authorization` (the key icon with an ×) in `Actions`.
5. Select `Confirm`.

##### From Account Credentials

Remove **one or all Bots' access to the selected credential**:

1. Open `Account Credentials` and select the credential's key icon in `Actions`.
2. In `Credential Authorize`, select `×` next to a Bot's name, or select `Clear All` to remove all Bot authorizations for this credential.
3. Select `Confirm` to save.

![Remove a Bot with the × next to its name, or select Clear All, then Confirm](/images/credential-revoke-bots.png)

Revoking access keeps the credential in Account Credentials. It does not sign out an active website session.

#### Delete a credential

Select the credential's trash icon in `Actions`. Deleting a credential prevents all authorized Bots from using it, so check which Bots depend on it first.

![Delete a credential with the trash icon in Account Credentials](/images/delete-credential.png)

### Credential notes

- Use credentials from your current company and authorize only the Bots that need them.
- Keep passwords and authenticator secret keys out of Build prompts and support messages.
- Workflow's `Login credential input parameters` collect values for each run. Use them when login values need to vary between runs; they are separate from saved credentials.

## Method 2: Import cookies

Import cookies from a signed-in website session to reuse it in your Bot. The website may still expire the session or require verification again.

### Export cookies from your local browser

The following example uses the **Cookie Editor** Chrome extension.

#### Step 1: Install Cookie Editor

Search for **Cookie Editor** in the Chrome Web Store, open its [extension page](https://chromewebstore.google.com/detail/cookie-editor/ookdjilphngeeeghgngjabigmpepanpl?hl=en), and select `Add to Chrome`.

![Find Cookie Editor in the Chrome Web Store and select Add to Chrome](/images/cookie-editor-install-chrome.png)

#### Step 2: Export the website's cookies

Open the website in Chrome and sign in to the account your Bot will use. Open **Cookie Editor**, select the **Export** icon, and choose **Netscape** or **JSON**. Keep the exported file or copied data.

![Open Cookie Editor on the target website and select Export](/images/cookie-editor-export-cookies.png)

#### Step 3: Import into BrowserAct

Upload the file or paste the data using the steps below.

### Import cookie data

Use **Standard Browser** and wait for all tasks in that browser to finish before importing.

1. Open the Bot's `Browser settings` → `Website login`.
2. Select `Import` on the `Import cookies` card.
3. Paste the data into `Cookie data`, or select `Upload cookie file` to upload a `.json`, `.txt`, or `.cookies` file.
4. Correct any validation errors, then select `Import cookies`.

![Upload a cookie file, then select Import cookies](/images/website-login-cookie-import-steps.png)

After a successful import, the card shows the cookie count and domains. BrowserAct saves the update for the Bot's future runs.

![The Import cookies card shows the imported cookie count and domains](/images/website-login-cookie-import-success.png)

### Update saved cookies

When cookies stop working, export a fresh signed-in session and repeat the import steps. If an import fails, BrowserAct keeps your input and the previous saved state.

### Supported formats and limits

| Requirement | Details |
| --- | --- |
| Formats | JSON Cookie Array or Netscape Cookie File. Plain Cookie Header Strings are not supported. |
| File types | `.json`, `.txt`, `.cookies` |
| Multiple domains | Allowed; each domain is counted separately. |
| Cookies per domain | Up to 180. Counting ignores leading dots and letter case, so `.EXAMPLE.com` and `example.com` count as the same domain. |
| Size per cookie | The `name=value` string must be no more than 4 KB (4,096 UTF-8 bytes). One oversized cookie causes the entire import to fail. |
| Total input length | No total character limit. Cookie format, required fields, domain counts, and individual cookie sizes are still checked. |

Include the cookies' domain and path information. A header string such as `name=value; name2=value2` does not contain this context. Follow any validation message below the input to correct your data.

## Method 3: Log in manually

Sign in yourself when a website needs direct verification, such as CAPTCHA, email or SMS codes, or single sign-on (SSO). Complete login in the Bot's browser so the session is available to that Bot.

For an email or SMS code, check your inbox or phone and enter the code in the website's verification field in the Bot's browser.

### Open the browser from Login settings

Use **Standard Browser** and wait for all tasks in that browser to finish.

1. Open the Bot's `Browser settings` → `Website login`.
2. Select `Open browser` on the `Log in manually` card.
3. Enter the website's URL in the browser's address bar.
4. Sign in and complete any required verification.
5. Select `Complete login` to save the session and return to the Bot's `Browser settings`.

![Select Open browser on the Log in manually card in Browser settings](/images/website-login-manual-browser.png)

### Complete login during Build

When Build asks for your help, select `Take over browser` in the latest request in the Build conversation.

![Select Take over browser when Build asks you to sign in](/images/website-login-build-assistance.png)

1. Sign in and complete any required verification.
2. Select `Return to Agent`.
3. Choose `Return without a note`, or add a short explanation and select `Send note & return`.

![Choose Return without a note or Send note & return after completing login](/images/website-login-build-return-note.png)

The optional note can contain up to **2,000 characters**. After you return, the same Build continues.

### Complete verification in a Workflow

A Workflow configured with a [Human Interaction node](/bot/workflow-built/node-types/human-interaction-node?co-from=link-Docs) can pause for verification. Follow its instructions and select `Resume` to continue the waiting Workflow.

### Time limits and incomplete login

| Login flow | How to finish | Time limit |
| --- | --- | --- |
| From settings | Select `Complete login` to save and return. | 15-minute browser session. |
| During Agent Build | Select `Return to Agent`, then return with or without a note. | Respond within the Build's one-hour waiting window. |
| Workflow Human Interaction node | Complete the requested actions and select `Resume`. | The time limit configured for that node. |

Follow the remaining time or deadline shown for your flow. If a Build assistance request expires, the current Build ends.

Canceling, timing out, or failing to save keeps the Bot's previous saved login state.

## Save and reuse login state

### How future runs use saved login

Standard Browser saves successful login updates from Build, manual login, cookie imports, and credential-based sign-in.

> **Saving an update does not change the website session in a task that is already running.** New tasks use the latest saved state available when they start. Running tasks keep the state they started with.

**Older task state does not overwrite a newer saved state.** Failed, canceled, or timed-out updates keep the previous saved state.

### When to update login

Update login if the website expires your session, signs you out, or requires new verification. Account or password changes may also require an update.

Clearing browser data or switching to Rotating Browser removes the saved sessions that depended on Standard Browser data. Editing, revoking, or deleting credentials affects future sign-in attempts; it does not automatically sign out an existing session.

## FAQ

### What should I do if a run fails because of login?

1. Once the browser has no running tasks, open your Bot's `Website login` settings.
2. Update credentials, import fresh cookies, or log in manually.
3. Save your changes and start a new run.

### Will the failed task continue after I fix login?

No. It stays **Failed**. Start a new run after updating login.

### Why can't I change Login settings?

Wait for all tasks in the Bot's browser to finish. Cookie import and manual login also require **Standard Browser**.

### Why does the website still ask me to sign in after importing cookies?

The session may have expired, or the website may require fresh verification. Import fresh cookies from a signed-in session, or log in manually.

### What should I do when BrowserAct emails me about login?

- **Build needs your help:** Select `Open Build` and complete the action before the email's deadline.
- **Login failed:** Select `Update login settings`, update login, then start a new run.
