Set up your Bot to access websites that require a login. BrowserAct supports three methods:

- <span id="method-1-use-account-credentials" /> **[Account credentials](/website-login/account-credentials?co-from=link-Docs):** Store login details in Account Credentials and authorize your Bot to use them.
- <span id="method-2-import-cookies" /> **[Import cookies](/website-login/import-cookies?co-from=link-Docs):** Reuse a website session you have already signed in to.
- <span id="method-3-log-in-manually" /> **[Manual login](/website-login/manual-login?co-from=link-Docs):** Sign in yourself in the Bot's browser.

This guide applies to your own Bots built with Agent or Workflow. You can combine methods, and your Bot reuses its setup across runs.

> For tasks that require login, we recommend **Standard Browser with a Static Proxy** to reuse your login session and keep a consistent IP address. [Learn how to purchase and use a Static Proxy](https://docs.browseract.com/browser-proxy/proxy/static-proxy-purchase-use?co-from=link-Docs#purchase-a-static-proxy).

## Choose the right login method

### Which method should I use?

| Your situation | Recommended method | How it helps |
| --- | --- | --- |
| The website uses authenticator-app two-factor authentication (2FA) | **Account credentials** | Add an Authenticator App Key so BrowserAct can generate supported time-based codes (TOTP). |
| The website has no 2FA | **Import cookies** or **Account credentials** | Reuse a signed-in session, or let the Bot sign in with saved credentials. |
| You do not want to store your password in BrowserAct | **Import cookies** | Sign in locally and import the session cookies. |
| The website frequently changes its login page | **Import cookies** | Reuse a signed-in session without relying on the login page's layout. |
| The website requires email or SMS verification | **Import cookies** or **Manual login** | Complete verification yourself, then import the session or save it in the Bot's browser. |
| You want to complete login or verification in the Bot's browser | **Manual login** | Open the browser, sign in, and save the session. |

**Standard Browser** supports all three methods and saves successful login updates for future runs. **Rotating Browser** supports authorized account credentials only and does not save its temporary session for future runs. Rotating Browser was previously named Private Browser.

![Rotating Browser supports Account credentials; Import cookies and Log in manually are unavailable](/images/website-login-rotating-browser-limits.png)

Credentials are the account details used to sign in. Login state is the browser session a website recognizes as signed in. Authorizing credentials or importing cookies does not guarantee that the website will accept the login.

### Open Login settings

**Agent Build:** Below the prompt input box, select `This website needs login` to use Standard Browser and open `Login settings`. Select the gear icon to reopen the panel. Leaving the checkbox unselected uses Rotating Browser.

![Select This website needs login below the Agent prompt to open Login settings](/images/website-login-agent-entry.png)

Credentials and cookies are optional before Build. BrowserAct first checks the existing session, then tries a matching authorized credential. If login still needs your help, Build requests manual assistance.

**Workflow Build:** Open the build canvas and select `Start`. Under `Default Browser`, turn on `This website needs login`. Use the gear icon to reopen `Login settings`.

![Open Login settings from Default Browser in the Workflow Start node](/images/website-login-workflow-entry.png)

The switch is on for Standard Browser and off for Rotating Browser. Turning it on saves Standard Browser. Turning it off requires confirmation to switch modes and clear Standard Browser history, cookies, and cache.

**Existing Bot:** Open the Bot's `Browser settings` tab and find `Website login`. After a Workflow Bot has been published, use this tab for login changes.

> **Login settings are locked while a task is running in the Bot's browser.** Wait for all tasks in that browser to finish before making changes.

![A running task blocks changes to the Bot's Login settings](/images/website-login-running-task-limit.png)

## Save and reuse login state

### How future runs use saved login

Standard Browser saves successful login updates from Build, manual login, cookie imports, and credential-based sign-in.

> **Saving an update does not change the website session in a task that is already running.** New tasks use the latest saved state available when they start. Running tasks keep the state they started with.

**Older task state does not overwrite a newer saved state.** Failed, canceled, or timed-out updates keep the previous saved state.

### When to update login

Update login if the website expires your session, signs you out, or requires new verification. Account or password changes may also require an update.

Clearing browser data or switching to Rotating Browser removes the saved sessions that depended on Standard Browser data. Editing, revoking, or deleting credentials affects future sign-in attempts; it does not automatically sign out an existing session.

## FAQ

### What should I do if a run fails because of login?

1. Once the browser has no running tasks, open your Bot's `Website login` settings.
2. Update credentials, import fresh cookies, or log in manually.
3. Save your changes and start a new run.

### Will the failed task continue after I fix login?

No. It stays **Failed**. Start a new run after updating login.

### Why can't I change Login settings?

Wait for all tasks in the Bot's browser to finish. Cookie import and manual login also require **Standard Browser**.

### Why does the website still ask me to sign in after importing cookies?

The session may have expired, or the website may require fresh verification. Import fresh cookies from a signed-in session, or log in manually.

### What should I do when BrowserAct emails me about login?

- **Build needs your help:** Select `Open Build` and complete the action before the email's deadline.
- **Login failed:** Select `Update login settings`, update login, then start a new run.
