# Workflow overview

结论：Workflow 是任务路径，不是新的产品层。它把 Skill 和 CLI 能力组合成常见操作场景。

## 选择工作流

| 目标 | 打开页面 |
| --- | --- |
| 读取受保护页面内容 | [Protected content](/workflow/protected-content) |
| 使用已有登录态或企业 SSO | [Logged-in automation](/workflow/logged-in-automation) |
| 多任务或多账号并行 | [Parallel sessions](/workflow/parallel-sessions) |
| 验证码、2FA 或人机阻塞 | [CAPTCHA handoff](/workflow/captcha-handoff) |
| 发现页面背后的 API | [Network capture](/workflow/network-capture) |

## 通用循环

```text
get-skills -> browser list -> browser open -> state -> action -> state -> close
```

最短命令：

```bash
browser-act get-skills core --skill-version <version>
browser-act browser list
browser-act --session task browser open <browser-id> https://example.com
browser-act --session task state
browser-act --session task session close task
```

## 安全基线

- 创建浏览器、删除浏览器、导入 Profile、切换代理或隐私模式前先确认。
- 对 `chrome-direct` 明确说明它会操作用户真实浏览器。
- 远程协助期间等待用户完成再继续。
- 每个任务结束后关闭 session。
