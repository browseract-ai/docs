Find and run BrowserAct Bots and official templates from your AI client.

## What you can do

MCP (Model Context Protocol) connects your AI client to BrowserAct. Search for Bots and templates, check inputs, run Tasks, and get results in your conversation.

Run accessible published Bots through the built-in tools. Expose settings are only needed for Custom tools.

**Connect → find a Bot or template → check inputs → run → get results.**

## Before you start

Use a BrowserAct account and a compatible MCP client. Publish your own Bots before running them. Official templates are ready to use. Set up website login first if your Bot needs it.

New connections use OAuth by default, without an API Key. Existing valid Key connections can continue to work. Setup options vary by client.

## Run Bots and Templates

### Run your published Bot

Describe your task or provide a Bot ID. Your agent checks required inputs, runs the Bot, and retrieves results.

```text
Run BrowserAct Bot [BOT_ID]. Ask me for any missing required inputs, then run once and retrieve the results.
```

### Run an official template

Describe your task or provide a template ID. Your agent checks required inputs, runs the template, and retrieves results.

```text
Run BrowserAct official template [TEMPLATE_ID]. Ask me for any missing required inputs, then run once and retrieve the results.
```

### Choose a proxy region for a template run

Ask your agent to find a supported region:

```text
Find the BrowserAct proxy region code for [country or region] and use it when I ask you to run official template [TEMPLATE_ID].
```

<span id="get-your-result" />

### Check progress and get results

A run returns a task ID. Keep it to check progress and retrieve results or available files.

Use `list_tasks` to find tasks, `get_task_status` to check progress, and `get_task` to get results. Use `cancel_task` to cancel a running or paused task.

### Rate limits and performance

There is no request rate limit. Concurrent task limits depend on your plan. Runs follow the existing credit rules; connecting does not start a run.

## Available tools

The unified connection provides 11 built-in tools. Access depends on the connected user and company.

| Tool name | Category | Enabled by default | Description |
| --- | --- | :---: | --- |
| `search_bots` | Bots | ✅ | Find published Bots accessible to your connected identity. |
| `get_bot_details` | Bots | ✅ | Get Bot details and input schema. |
| `run_bot` | Bots | ✅ | Run a published Bot and return a task ID. |
| `search_official_templates` | Templates | ✅ | Find available official templates. |
| `get_official_template_details` | Templates | ✅ | Get template details and input schema. |
| `run_official_template` | Templates | ✅ | Run an official template and return a task ID. |
| `list_proxy_regions` | Regions | ✅ | List supported proxy region codes and names. |
| `list_tasks` | Tasks | ✅ | Find existing tasks and their IDs. |
| `get_task_status` | Tasks | ✅ | Get the current task status. |
| `get_task` | Tasks | ✅ | Get task details, output, and available files. |
| `cancel_task` | Tasks | ✅ | Cancel a running or paused task. |

Exposed, accessible Custom tools appear alongside these tools. After changing Custom configuration, refresh the client's tool list. A valid authorization does not need renewed consent for this refresh.

## Manage your MCP connections

### View authorized clients

1. Open **[API & Integrations](https://www.browseract.com/reception/integrations?co-from=link-Docs)**.
2. Find **Authorized MCP Clients** below **API Keys**.
3. Review the client, source, grant ID, and **Authorized** time.
4. Click **Refresh** to update the list.

![View Authorized MCP Clients below API Keys and refresh the list](/images/global-mcp/authorized-mcp-clients.png)

### Automatic renewal and reconnecting

Your client refreshes OAuth credentials automatically. Access Tokens last **2 hours**. Refresh Tokens expire after **30 days without a successful refresh**; each successful refresh restarts the period.

### Revoke access

Click **Revoke** and confirm. Successful revocation stops new access and refreshes across that grant's credentials. Already authenticated requests may finish; started Tasks keep running.

### Account changes and API Keys

Website logout, password changes, and account switching do not revoke OAuth grants or switch an existing MCP connection. Select or authorize another identity in your client.

Manage Keys in **[API & Integrations](https://www.browseract.com/reception/integrations?co-from=link-Docs) → API Keys**. Revoking a API Key stops every connection using it. OAuth grants must be revoked separately.

## Troubleshooting and FAQ

### Check the reported problem

| Problem | What to check |
| --- | --- |
| OAuth authorization fails | Return to the client and check its connection status. If authorization is still needed, start a new request there. Confirm the account and complete Allow access. |
| An old authorization link shows an error | Check whether the client is already connected. Close the old page if it is; otherwise, start a fresh authorization request from the client. |
| The login account changed during authorization | Review the updated account on the authorization card and decide again. Do not assume the original account was authorized. |
| API Key authentication fails | Use a valid API Key and `Authorization: Bearer …`. Check that the Key has not been revoked. |
| I see tools but not individual Bots | Bots and templates are discovered through search rather than all listed individually. Use search_bots or search_official_templates. Exposed Custom tools have their own visibility rules. |
| A Custom tool disappeared | Check Server status, Expose settings, the published Bot, and current permissions. Reauthorizing alone cannot restore a disabled resource. |
| Input validation fails | Read the current resource details. Supply required fields with the correct types. Check descriptions and defaults. |
| A run returned only an ID | This is expected. Query status, then retrieve the task result. |
| A run submission timed out | The request may already have created a task. Check by task ID, or reconcile the original submission before retrying. Do not submit a duplicate while the outcome is uncertain. |
| A region is rejected | Call list_proxy_regions and select a returned code. |
| A run fails | Read task details. Address the reported permission, input, balance, or website-access issue before choosing to run again. |

### Frequently asked questions

**Can I use the same API Key for global and Custom MCP connections?**

Yes. A API Key works with unified MCP, Custom Server URLs, and supported public REST APIs, subject to current permissions. Manage it in **[API & Integrations](https://www.browseract.com/reception/integrations?co-from=link-Docs) → API Keys**. Use separate Keys for independent revocation.

**Do I need an API Key for OAuth?**

No. Sign in and authorize BrowserAct. Existing valid Key connections can still be used.

**Do I need to expose each Bot before using BrowserAct MCP?**

No. Built-in tools can find accessible Bots and run published Bots. Expose settings apply to Custom tools.

**Does one authorization cover every client or company?**

No. Each grant belongs to a user, company, and client. Authorize other clients or identities separately. Switching website accounts does not switch an existing connection.

**Does granting access run a Bot?**

No. A Task starts when you request a run and provide the required inputs.

**Can I change the tool list with a URL parameter?**

No. Use Custom Server Expose settings; URL `?tools=` filtering is not supported.

**Can I resume a task through MCP?**

No. Check the task details to decide your next step.
