---


自动化卡住时把控制权交给人——任意设备打开链接即可接管，处理完 Agent 无缝继续。

## 一行命令交给人

```bash
browser-act --session my-task remote-assist --objective "完成 2FA 验证"
```

CLI 返回一个实时远程 URL。

## 任意设备接管

用户在任何设备的任何浏览器中打开这个链接，就能看到浏览器画面并操作：

- 笔记本 / 台式机
- 手机 / 平板
- 远程服务器场景（从自己设备接管）
- SSH 远程开发场景

**无需切回 headed 模式、无需在同一台机器、无需安装任何软件。** 不依赖屏幕共享、不依赖 VNC，一个链接，浏览器原生支持。

## 典型场景

| 场景 | 解决方式 |
|------|----------|
| 需要手机的双因素认证 | 用户在手机上接收短信/App 验证码并输入 |
| 自动解决不了的复杂验证码 | 拖拽拼图、行为验证等 |
| 需要硬件令牌的企业 SSO | UKey、动态口令卡等本地硬件设备 |
| 工作流中间需要人类判断 | 多个候选项中做选择、合规审核、敏感操作前确认 |
| 多人协作 | 把链接发给同事帮忙完成验证 |

## 接管完成后无缝继续

人完成验证后：
- 不需要重启会话
- 不丢失自动化上下文
- 浏览器状态、Cookie、当前页面位置全部保留
- Agent 直接从下一步继续执行

## 与标准方案对比

| | 标准方案 | Browser-act |
|---|---|---|
| headless 时如何让人介入 | 必须切回 headed | 直接生成远程 URL |
| 需要人在同一台机器 | 是 | 否 |
| 需要装额外软件（VNC/RDP/屏幕共享） | 是 | 否 |
| 跨设备接管 | 不支持 | 任意浏览器即可 |
| 用户完成后 | 手动重启会话 | Agent 自动继续 |
