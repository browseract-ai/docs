# How the Skill Works

BrowserAct Skill is intentionally small. It tells the Agent how to find BrowserAct, when to call `get-skills`, and how to follow safety rules before using the CLI.

The detailed instructions come from the CLI at runtime.

## Two layers

```text
Entry Skill
  -> stable, lightweight routing instructions

get-skills runtime
  -> current CLI version, browser list, sessions, auth status, commands, and safety rules
```

The entry Skill stays stable. The runtime instructions change with your local environment and BrowserAct CLI version.

## What the Agent does

1. The user asks for browser automation.
2. The Agent recognizes that BrowserAct can help.
3. The Agent runs `browser-act get-skills core --skill-version <version>`.
4. The CLI returns the current browser, session, auth, command, and safety context.
5. The Agent chooses a browser and session.
6. The Agent asks for confirmation before sensitive operations.
7. The Agent runs CLI commands and closes the session when the task is done.

## Why runtime instructions matter

- CLI commands can change over time.
- Browser lists, API Key state, and active sessions are local runtime state.
- Most tasks only need core instructions.
- Advanced guidance can be loaded only when needed.

## Example

```bash
browser-act get-skills core --skill-version <version>
browser-act browser list
browser-act --session research browser open <browser-id> https://example.com
browser-act --session research state
```
