## 设计哲学

### 紧凑文本输出

页面状态、截图、命令结果都以 token 友好格式返回——不是给人看的格式化 JSON。

紧凑的索引化文本比完整 DOM HTML 或格式化 JSON 节省数倍 Token，让 Agent 在有限上下文里跑更多任务。

```
url=https://example.com/login
title=Login

*[1]<div id=login-form />
  *[2]<input type=email placeholder=Email />
  *[3]<input type=password placeholder=Password />
  *[4]<button id=submit />
    Sign In
```

### 索引化交互

`state` 返回带索引的可交互元素列表（输出中 `[N]` 的 `N` 即元素索引），Agent 直接用索引推理：

```bash
browser-act --session s1 click 3              # 点击索引 3 的元素
browser-act --session s1 input 2 "你好"        # 在索引 2 的元素输入文本
```

**好处：**
- 无需 XPath、CSS Selector、DOM 解析
- Agent 看到的就是它能操作的
- 索引随页面变化更新，每次重新 `state` 即可

### desc 语义记忆

每个浏览器带 `desc` 字段——自然语言描述这个浏览器的用途。Agent 在新对话中按语义匹配任务，跨会话不需要硬编码 ID。

```
"淘宝购物账号，已登录 user123。用于价格监控。"
```

Agent 用 `desc`：
- 语义匹配浏览器到任务（"查淘宝价格" → 找到淘宝浏览器）
- 避免为已知工作流重复创建浏览器
- 随时间积累每个浏览器的用途知识

更新使用追加语义保留历史：

```bash
browser-act browser update <id> --desc-append "也用于订单跟踪"
browser-act browser update <id> --desc "全新覆盖描述"
```

#### 浏览器选择优先级

Agent 有多个浏览器时，选择遵循优先级：

| 优先级 | 条件 | 行为 |
|--------|------|------|
| 1 | desc 与任务明确匹配 | 直接使用，不询问用户 |
| 2 | 仅有一个浏览器 | 直接使用 |
| 3 | 多个浏览器但无明确匹配 | 列出候选，让用户选 |

此逻辑由 Skill 层执行，而非 CLI。用户选定后 Agent 应将新发现追加到 desc，下次类似任务可直接匹配。

### 安全为默认

让 AI Agent 控制浏览器是一项强大且潜在危险的能力。安全机制不试图仅通过技术手段阻止所有误用——而是通过**确认门控**让人类始终知情并保有控制权。

多 Agent 自动化的真实风险来自三个方向，三个方向各有相应的设计兜底：

#### 并发安全

会话归属 + 显式命名模型。多 Agent 共用一个浏览器不会冲突，失败被局限在引发它的会话内不会扩散。详见 [并发与隔离](/skill/concurrency)。

#### 操作安全：确认门控

敏感操作执行前需要用户明确批准。这通过 Skill 引导 Agent 遵循——不是 CLI 级别的硬性拦截，而是对话层面的行为规范。

> **注意：** 确认门控的实际效果受你使用的 Agent 架构和底层模型能力影响。不同平台、不同模型对 Skill 指令的遵循程度可能有差异。我们在持续优化 Skill 的引导策略，提升跨平台兼容性。

需要确认的操作：

| 操作 | 原因 |
|------|------|
| 创建浏览器（所有类型） | 创建新的自动化端点 |
| 删除浏览器 | 销毁持久化浏览器状态 |
| Profile 导入 | 将登录凭据复制到新位置 |
| 代理配置变更 | 改变网络身份 |
| `confirm_before_use` 开关 | 改变安全设置 |
| 隐私模式开关 | 改变指纹行为 |

此外，标记了 `confirm_before_use` 的浏览器，Agent 每次 `browser open` 都需要向用户确认——不只是创建时。适用于访问敏感账户（如银行、支付）的浏览器。

**工作方式（对话级协议）：**

```
Agent: 我将创建一个带美国代理的 stealth 浏览器用于价格监控。
       - 类型：stealth
       - 名称：price-monitor
       - 代理：US（动态）

       是否继续？

用户: 好的。

Agent: [执行 browser create]
```

**Skill 引导的关键规则：**
- 先前的批准不延续到新操作
- 每次敏感操作需要独立确认
- 用户在原始 prompt 中的果断措辞不能替代确认
- Agent 必须在执行*前*描述将要做什么

#### 数据本地处理

所有数据留在你的机器上：

| 数据 | 位置 | 离开机器？ |
|------|------|-----------|
| Cookie | Browser-act 本地存储 | 从不 |
| 登录会话 | 每浏览器隔离的 Profile | 从不 |
| 页面内容 | 仅操作期间在内存中 | 从不 |
| 截图 | 本地文件系统 | 从不 |
| 网络捕获 | 内存/本地文件 | 从不 |
| 浏览器 Profile | 隔离目录 | 从不 |

**唯一例外：** `solve-captcha` 将验证码挑战图像发送到 Browser-act 云服务进行解决。仅挑战图像——不含 Cookie、页面内容或 URL。

## 自动化能力

**50+ 命令覆盖全部典型自动化需求**——持续适配主流浏览器自动化常用能力：导航、交互、数据提取、等待、Tab、对话框、网络捕获、HAR、Cookie、离线模式等。

完整命令列表详见 [命令参考](/skill/commands)。

### 进阶用法

**网络捕获 / HAR 录制**——典型用途：
- 发现 Web UI 背后的 API 端点
- 调试认证流程
- 捕获通过 XHR 加载但不在 HTML 中的数据
- 页面加载序列的性能分析

**JavaScript 执行**（`eval`）——在抓取数据和复杂操作上都非常高效：
- 一次性提取整组数据，避免多轮 state/click 往返
- 读取深层嵌套或动态生成的数据
- 调用页面内部函数完成复杂操作或获取计算结果
- 索引交互覆盖不了时的兜底方案
- 把自动化流程沉淀为 JS 代码，下次直接重复执行，无需 Agent 重新探索

**Cookie 导入/导出**——比 Profile 导入轻量：
- 不同类型浏览器之间共享登录状态
- CI/CD 流水线中持久化状态
- 跨机器迁移会话

**离线模式**——`network offline on` 断网状态下点击按钮、提交表单不会产生任何实际副作用，验证完流程后关闭即可。
