# Sessions

A session is the task handle for BrowserAct browser operations. Any command that interacts with a page should use a clear `--session` name.

## Why sessions matter

Sessions make browser automation safer:

- They keep parallel tasks separate.
- They make ownership clear.
- They give each task a lifecycle the Agent can close.

```bash
browser-act --session price-check browser open <browser-id> https://shop.example.com
browser-act --session price-check state
browser-act --session price-check click 5
browser-act --session price-check session close price-check
```

## Lifecycle

```text
create -> use -> close
```

The first `browser open` with a session name creates the session. Later commands with the same name reuse that browser window. Close the session when the task is done.

```bash
browser-act --session monitor browser open abc123 https://site.com
browser-act --session monitor get markdown
browser-act --session monitor session close monitor
```

## Parallel sessions

One browser can host multiple sessions. They can share login state, but navigation, tabs, and network capture remain separate.

```bash
browser-act --session task-a browser open abc123 https://site.com/page1
browser-act --session task-b browser open abc123 https://site.com/page2
browser-act --session task-a click 3
browser-act --session task-b input 1 "keyword"
```

For the same account, prefer multiple sessions in one browser. Use separate browsers when identities or accounts must be isolated.

## Ownership rule

`session list` shows active sessions. An Agent should not take over a session it did not create. Start a new session for a new task.

```bash
browser-act session list
```

## Commands that do not need a session

System and browser-management commands do not need `--session`:

- `browser list`, `browser create`, `browser update`, `browser delete`
- `browser regions`, `browser list-profiles`
- `session list`
- `auth login`, `auth poll`, `auth set`, `auth clear`
- `get-skills`, `report-log`, `feedback`
- `stealth-extract`

## Best practices

- Use a descriptive name such as `check-price`.
- Keep one logical task in one session.
- Close the session when done.
- Do not reuse sessions created by another Agent or conversation.
