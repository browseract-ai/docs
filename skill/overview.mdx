BrowserAct has two entry points:

- Skill: for AI agents. It teaches an Agent how to safely use the BrowserAct CLI to operate browsers.
- Workflow: for users and teams. It lets you build hosted browser automations on a visual canvas, using AI-driven nodes described in natural language.

Skill helps AI agents operate browsers. Workflow helps users and teams turn repeated browser tasks into hosted, reusable, observable automation flows.

## Why Workflow exists for browser automation

Traditional browser automation often depends on scripts, selectors, and fixed flows. When a page changes, scripts can break. It is also hard for business users to build and maintain these automations on their own.

BrowserAct Workflow turns browser automation into a hosted visual canvas. Users choose node types, describe what each node should do in natural language, and BrowserAct AI uses the current page state to drive the browser at runtime.

Workflow is not documentation. It is designed to turn one-off web tasks into reusable, hosted, observable, and schedulable automation flows with execution history.

## Example: natural-language browser node

A script-based approach might look like this:

```js
click("#export-button")
```

In BrowserAct Workflow, a user can choose a Click node and write:

```text
Click the Export CSV button in the top-right corner of the page.
```

At runtime, AI reads the page state, finds the button that best matches the instruction, and clicks it.

More node examples:

- Extract node: Extract the order ID, amount, and status from the table.
- Input node: Enter the customer email into the search box and submit the query.
- Condition node: If the order status is Pending, route the run to a human review branch.

## Skill / CLI / Workflow relationship

| Layer | Definition |
| --- | --- |
| Skill | Agent entry layer. Gives agents browser automation capability. |
| CLI Runtime | Execution layer. Performs browser operations. |
| Workflow | Hosted orchestration layer. Turns repeated browser tasks into visual, natural-language, AI-driven automation flows. |

Skill teaches the Agent how to use BrowserAct. `get-skills` gives the Agent runtime-aware instructions. CLI Runtime performs browser operations. Workflow productizes repeated browser automations as hosted node graphs.

Workflow can use BrowserAct browser automation capabilities, but Workflow is not documentation, task guides, or API reference.

## Minimum agent startup sequence

```bash
browser-act get-skills core --skill-version <version>
browser-act browser list
browser-act --session my-task browser open <browser-id> https://example.com
browser-act --session my-task state
browser-act --session my-task session close my-task
```

Ask for user confirmation before sensitive operations, such as creating or deleting browsers, importing profiles, changing proxy or privacy settings, or using a `confirm_before_use` browser.
