# Stealth and Extraction

Use `stealth-extract` when the Agent only needs to read content from a page. Use a stealth browser when the task needs stateful interaction, clicks, input, or multi-step navigation.

## Three levels of handling

```text
environment -> verification handling -> human handoff
```

Most read-only extraction starts at the environment level. If a verification step appears, the Agent can try `solve-captcha`. If the step needs human judgment, use headed mode or remote assist.

## Zero-setup extraction

```bash
browser-act stealth-extract https://protected-site.com
```

Common options:

```bash
browser-act stealth-extract https://example.com --content-type html
browser-act stealth-extract https://example.com --dynamic-proxy US
browser-act stealth-extract https://example.com --custom-proxy socks5://host:port
browser-act stealth-extract https://example.com --timeout 60
browser-act stealth-extract https://example.com --output ./result.md
```

Use this path for read-only extraction. It opens a stealth browser, waits for content, returns the result, and cleans up.

## Full stealth browser

Use a stealth browser for protected pages that need interaction:

```bash
browser-act browser create \
  --type stealth \
  --name "competitor-monitor" \
  --desc "Competitor price monitoring" \
  --dynamic-proxy US

browser-act --session monitor browser open <stealth-id> https://protected-site.com
browser-act --session monitor state
```

Creating a stealth browser, setting a proxy, or changing private mode is sensitive. Ask for user confirmation first.

## CAPTCHA and human handoff

```bash
browser-act --session s1 solve-captcha
browser-act --session s1 remote-assist --objective "Please complete the CAPTCHA"
```

After `remote-assist`, the Agent should stop sending browser commands until the user says the manual step is complete.
