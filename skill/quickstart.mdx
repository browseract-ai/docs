# Quickstart

Use BrowserAct when an Agent needs to read, click, type, extract, or inspect a real browser page.

Start with the simplest path that fits the job: use `stealth-extract` for read-only content extraction, and use a named session when the Agent needs to interact with a browser.

## Extract page content

```bash
browser-act stealth-extract https://example.com
```

This opens a stealth browser, waits for the page to render, returns page content as markdown, and cleans up the run context.

Common options:

```bash
browser-act stealth-extract https://example.com --content-type html
browser-act stealth-extract https://example.com --dynamic-proxy US
browser-act stealth-extract https://example.com --output ./result.md
```

## Open a browser and interact

```bash
browser-act browser list
browser-act --session my-task browser open <browser-id> https://example.com
browser-act --session my-task state
browser-act --session my-task click 2
browser-act --session my-task state
browser-act --session my-task session close my-task
```

`state` is the Agent's main observation command. It returns the current URL, page title, and indexed interactive elements. The next command can use those indexes.

## Basic loop

```text
open -> state -> act -> state -> close
```

Read the page state before deciding what to do next. Use separate commands when the next step depends on page output.

## Choose a path

| Goal | Recommended path |
| --- | --- |
| Read page content only | `stealth-extract` |
| Click, type, submit forms, or log in | `browser open` with a named session |
| Use existing login state | `chrome` with profile import |
| Use enterprise SSO or browser extensions | `chrome-direct` |
| Work with protected or geo-sensitive pages | `stealth browser` or `stealth-extract` |
| Handle a CAPTCHA block | `solve-captcha`, then `remote assist` if needed |
